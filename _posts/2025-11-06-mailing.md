# Attack
## Recon
Config host để đỡ phải nhớ ip. Bằng cách thêm dòng `10.129.232.39 mailing.htb` vào cuối file `/etc/hosts`.

Scan `nmap`
```
nmap -p- 10.129.232.39 -vv -n -Pn
```

## Explore Web 
Truy cập vào thì mình thấy đây có vẻ giống như là một trang quản bá sản phẩm và doanh nghiệp. Cụ thể ở đây là sản phẩm **hMailServer**.

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2015.05.08.png)

Cuối trang có một button để download file hướng dẫn cài đặt sản phẩm.
Nếu rê chuột vào button bạn sẽ thấy trang sẽ redirect đến path `/download.php?file=file-name` để thực thi script `download.php` và download một file nào đó bất kỳ.

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2015.06.31.png)

Từ cách hoạt động này mình đoán khả năng endpoint này tồn tại lỗ hổng **path traversal** ⟹ đi chứng minh giả thuyết đã đặt ra thôi.
## Path Traversal Attack
Đầu tiên mình phải xác định được server này đang chạy OS nào, cụ thể là **Linux** hay **Windows**.
Có một mẹo mình hay dùng để xác định OS (cũng không hẳn là chính xác 100% đou nha 🤪) là `ping` đến server đó. Nếu `65 < ttl < 128` ⟹ **Windows** còn `ttl <= 64` ⟹ **Linux**

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2015.15.20.png)

⟹ Dự là **Windows**. Tìm wordlist path traversal Windows đi fuzz thôi hí hí.

Fuzz mụt hồi thì tìm được cái path `../../windows/win.ini` có sự khác lạ.

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2015.17.42.png)

⟹ Tỉ lệ đây là bug **path traversal** đã được tăng lên. Cơ mà giờ phải làm gì tiếp theo nhỉ ?
Nhớ lại cái web app, mình chưa thử download file hướng dẫn về mà nhỉ ?

Đúng là file hướng dẫn, nó chỉ hướng dẫn mình cách setup hMailServer trên các OS. Tuy nhiên trong file hướng dẫn mình tìm được những thông tin như là .....

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2015.23.40.png)

`maya@mailing.htb`. Mình sẽ xem như đây là một account leak.

Hmm, nếu vậy khả năng server này cũng sẽ đang chạy **hMailServer**. Để đi search về các thông tin default của nó xem sao.

Sau khi search thì mình biết được rằng là nó có một file config mặc định nằm ở path `C:\Program Files (x86)\hMailServer\Bin\hMailServer.ini`.
Tuy nhiên mình đã thử các thứ nhưng không được ⟹ thật là không hiểu.

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2015.48.19.png)

🤔🤔🤔 à há nếu không dùng **đường dẫn tuyệt đối** được thì thử dùng **đường dẫn tương đối** xem sao nhỉ.
Bởi vì hồi nãy mình có fuzz `../../windows/win.ini` ⟹ back ra 2 thư mục sẽ ở `C:`. Vậy cuối cùng thì ghép path vào sẽ là `../../Program+Files+(x86)/hMailServer/Bin/hMailServer.ini`

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2016.36.00.png)
## Crack hash
Từ `AdministratorPassword=841bb5acfa6779ae432fd7a4e6600ba7` mình có được hash của tài khoản `Administrator`. Chạy lệnh crack nó nào.
```
hashcat -a 0 -m 0 841bb5acfa6779ae432fd7a4e6600ba7 <path-to-file-rockyou.txt>
```

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2017.10.15.png)

⟹ pass `Administrator` là `homenetworkingadministrator`.

Vừa có acc là mình đi login liền nhưng mà đời đâu như là mơ.

![Screenshot](/assets/htb/Screenshot%202025-11-06%20at%2017.15.14.png)

Vậy chắc là account này chỉ để login vào cái mail trên thôi.

# Privilege
## BloodHound
Mình sẽ sử dụng **bloodhound-python** để lấy toàn bộ thông tin từ tầm nhìn của user **support** trong domain để có cái nhìn tổng quát.
```
bloodhound-python -u 'support' -p 'Ironside47pleasure40Watchful' -ns 10.129.230.181 -d support.htb -dc support.htb -c all --zip
```

![Screenshot](/assets/htb/Screenshot%202025-11-02%20at%2023.29.34.png)

Sau khi dump thông tin domain từ user **support** chúng ta có được file **.zip**. Tiến hành upload file **zip** đó vào **bloodhound-gui** để xem map 😜. `Upload Data` ⇨ `Chọn đến file zip`.

Sau khi quá trình upload hoàn thành, mình sẽ search user **support** để kiểm tra các quyền có thể có của nó. Đầu tiên mình sẽ set cho **bloodhound** biết rằng user này mình đã chiếm được quyền bằng cách `Click phải vào node user vừa sinh ra` ⇨ `Mark User as Owned`.

![Screenshot](/assets/htb/Screenshot%202025-11-02%20at%2023.26.19.png)

Bây giờ mình sẽ xem user mình đang sở hữu thuộc những group nào và có những quyền gì ?

![Screenshot](/assets/htb/Screenshot%202025-11-03%20at%2000.45.38.png)
![Screenshot](/assets/htb/Screenshot%202025-11-03%20at%2000.46.49.png)

User mà chúng ta có thuộc 3 group, tuy nhiên chỉ có mỗi group **SHARED SUPPORT ACCOUNTS** là có hướng đi và đi đến **DC.SUPPORT.HTB** như hình dưới.

![Screenshot](/assets/htb/Screenshot%202025-11-03%20at%2000.39.26.png)
![Screenshot](/assets/htb/Screenshot%202025-11-03%20at%2000.52.22.png)
![Screenshot](/assets/htb/Screenshot%202025-11-03%20at%2011.19.53.png)

Như hướng đi mà **Bloodhound** gợi ý cho mình, thì mình sẽ tìm cách chiến quyền điều khiển của máy tính **dc.support.htb** từ máy tính này mình sẽ có quyền **GetChangesAll (Replicating Directory Changes All)**, từ đó mình có thể sử dụng kỹ thuật **DCSync attack** để dump toàn bộ credential hash của domain.

Suy ngược lại vấn đề, vậy khi đang có toàn quyền trên user **support** thì mình sẽ phải làm gì để chiếm được quyền điều khiển máy **dc.support.htb** nhỉ ?

![Screenshot](/assets/htb/Screenshot%202025-11-03%20at%2011.33.53.png)

Khi bấm vào **help** bên trong **bloodhound** có hướng dẫn mình **Lateral Movement** qua máy **dc.support.htb** bằng kỹ thuật [Kerberos Resource-based Constrained Delegation](https://www.ired.team/offensive-security-experiments/active-directory-kerberos-abuse/resource-based-constrained-delegation-ad-computer-object-take-over-and-privilged-code-execution).

Để thực hiện kỹ thuật này mình phải tạo một máy tính giả mạo để có một identity kiểu computer mà chính mình kiểm soát *khoá/mật khẩu* và một *SID* để inject attribute `msDS-AllowedToActOnBehalfOfOtherIdentity` trên máy tính cần chiếm quyền kiểm soát (dc.support.htb).
### Check environment
Để chạy được các command check môi trường thì minh cần có [PowerView](https://github.com/PowerShellMafia/PowerSploit/blob/master/Recon/PowerView.ps1) script và import nó vào module của powershell.

![Screenshot](/assets/htb/Screenshot%202025-11-04%20at%2016.54.09.png)

#### Check ms-ds-machineaccountquota
Thông thường cứ mỗi member trong domain đều có thể thêm được 10 computers vào domain để kiểm tra user này còn slot thêm computer vào domain không thì mình sẽ chạy lệnh:
```
Get-DomainObject -Identity "dc=support,dc=htb" -Domain support.htb
```
Và check giá trị tham số `ms-ds-machineaccountquota`.

![Screenshot](/assets/htb/Screenshot%202025-11-04%20at%2010.35.40.png)

### Create a new Computer Object
**Bloodhound** có hỗ trợ chúng ta các command để tạo một Computer Object và cũng như các cách khai thác để hoàn thành việc leo quyền.

![Screenshot](/assets/htb/Screenshot%202025-11-04%20at%2011.32.00.png)
![Screenshot](/assets/htb/Screenshot%202025-11-04%20at%2014.34.29.png)

Mình sẽ thực hiện chạy từng command một.
```
addcomputer.py -computer-name 'd7cky$' -computer-pass 'D7ckyduck' -dc-ip support.htb 'support.htb/support:Ironside47pleasure40Watchful'
```

![Screenshot](/assets/htb/Screenshot%202025-11-04%20at%2014.52.59.png)

Bước này mình tạo một computer với user `d7cky` pass `D7ckyduck`. `Do computer d7cky mình đã tạo trước đó rồi nên khi chạy command nó báo đã tồn tại`.

```
rbcd.py -delegate-from 'd7cky$' -delegate-to 'DC$' -action 'write' 'support.htb/support:Ironside47pleasure40Watchful'
```

Bước này mình viết một entry `msDS-AllowedToActOnBehalfOfOtherIdentity` đến tài khoản `DC` bằng tài khoản `support` để cho account computer `d7cky` của mình vừa tạo ra có thể mạo danh bất kỳ user tới dịch vụ trên `DC` (tức DC sẽ chấp nhận principal `d7cky$` để act-as).

![Screenshot](/assets/htb/Screenshot%202025-11-04%20at%2014.54.26.png)

```
getST.py -spn 'CIFS/dc.support.htb' -impersonate 'administrator' 'support.htb/d7cky$:D7ckyduck'
```

Bước này mình sử dụng tài khoản computer giả mạo để lấy Service Ticket (TGS) tới Service Principal Name (SPN) `cifs/dc.support.htb` thay mặt `Administrator`. Nếu thành công thì mình có thể dùng ticket đó truy cập CIFS (SMB) trên `dc.support.htb` như Administrator.

![Screenshot](/assets/htb/Screenshot%202025-11-04%20at%2014.57.56.png)

Mặc định biến môi trường `KRB5CCNAME` sẽ chỉ cho thư viện Kerberos đường dẫn tới file ccache, vì thế mình sẽ gán biến môi trường tới file ccache vừa tạo ra.
```
export KRB5CCNAME=`pwd`/administrator@CIFS_dc.support.htb@SUPPORT.HTB.ccache
```
Sau đó mình sử dụng `psexec` để sử dụng ticket authen bằng Kerberos.
```
psexec.py -k dc.support.htb
```
